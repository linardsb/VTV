# Agent Module

Pydantic AI agent (`Agent[UnifiedDeps, str]`) with 11 tools across 4 domains. Follows vertical slice pattern with `tools/` subdirectory.

## Directory Structure

```
app/core/agents/
├── agent.py           # Agent creation, 11 tool registrations + build_instructions_with_skills()
├── routes.py          # /v1/chat/completions, /v1/models, /v1/chat/metrics (admin-only correction metrics, AI-5.3) — rate limited + quota. AI-6.3: when `agent_multi_agent_enabled` flag is on and incoming `body.agent == "unified"`, the most-recent user message is fed through `AgentRouter.route()` to upgrade `"unified"` to a domain-specific agent before resolution
├── router.py          # AI-6.3: heuristic AgentRouter — keyword-regex scoring of prompts against transit/knowledge/vault signal sets. Returns `RoutingDecision(domain, transit_score, knowledge_score, vault_score)`. Tied or zero-score prompts fall back to `"unified"`. LLM-free, microsecond classification, mirrors `routing.py` design. Logs `agent.router.decision` with `prompt_hash` (12-char SHA-256, never raw prompt). Singleton via `get_agent_router()`. Gated by `agent_multi_agent_enabled` config flag (default off)
├── base.py            # AI-6.1: BaseAgentService harness — shared pipeline orchestrator owning the order: tier → prompt injection detection (AI-9.1 detection + AI-9.2 blocking: `detect_injection()` from `injection_detector.py`, mode-aware gate raises `PromptInjectionBlockedError` → HTTP 400 when `prompt_injection_mode="block"` and confidence >= threshold, otherwise logs with threshold-based level) → RAG routing → skills → memory → system prompt → validation cache preload → execute → post-process (QA footnotes) → **AgentResult wrapper (AI-6.5)** → **confidence re-route gate (AI-6.5, single retry to complex tier when confidence < threshold)** → response assembly → chat_started/completed logging → AgentExecutionError wrapping. Exposes 11 hook points (_get_model_tier, _apply_rag_routing, detect_relevant_skills, _recall_memories_block, build_system_prompt, _build_user_message, _preload_validation_cache, _execute [MUST override], _post_process/_run_qa/_should_run_qa, _build_response, _persist_episode). `_PipelineOutcome` extended with optional `confidence: float | None` + `tools_used: tuple[str, ...]`. Abstract for concrete subclasses.
├── service.py         # AgentService(BaseAgentService) — transit-domain concrete subclass. Overrides hooks that touch test-patched service-module globals (needs_rag, MemoryService, SkillService, agent, get_settings, build_instructions_with_skills, validate_transit_response, persist_agent_episode). Owns UnifiedDeps injection, SelfCorrectionLoop wiring, complex-pipeline dispatch, and the singleton lifecycle (get_agent_service / close_agent_service). Module-level __all__ explicitly re-exports every patched symbol. AI-8.3: `_execute()` is a 3-helper dispatch (`_execute_complex_tier`, `_execute_correction_tier`, `_execute_fallback_tier`); each helper wraps its LLM call in a closure run through `llm.invoke_provider_chain()`. Per-iteration observability is preserved by `track_provider_call(None, provider_name)` inside each closure so the chain provider name (not the tier-model class name) keys both the breaker registry and the AI-8.2 health tracker. `_execute()` catches `AllProvidersUnavailableError` and returns a static, user-safe degraded `_PipelineOutcome` ("All LLM providers are temporarily unavailable…") with `confidence=None` (skips the AI-6.5 re-route gate) and `warnings=[]` (skips QA + footnote rendering). Provider names never leak into user-facing content (CTX-AGENT).
├── schemas.py         # OpenAI-compatible request/response schemas
├── config.py          # LLM provider settings (model names, tokens, timeouts)
├── routing.py         # Multi-tier model routing (fast/standard/complex classification)
├── quota.py           # Daily per-IP quota tracker (50/day, auto-reset)
├── injection_detector.py # AI-9.1: OWASP LLM01 taxonomy prompt injection detection — 31 compiled regex patterns across 6 categories (override, role_hijack, extraction, delimiter_escape, tool_misuse, encoding), EN/LV multi-language, per-match `InjectionSignal` with confidence scoring (0.0-1.0), `InjectionResult` with aggregate confidence + multi-signal boost (cross-category >=2 → +0.10, same-category >=2 → +0.05, capped 0.95), Cyrillic homoglyph normalization (NFKD + 8-char map), `InjectionDetector` class with customizable pattern catalog, module-level `detect_injection()` singleton convenience function. AI-9.2: blocking mode added — when `prompt_injection_mode="block"` and confidence >= `prompt_injection_block_threshold` (0.85), raises `PromptInjectionBlockedError` → HTTP 400 before LLM call. Default `mode="warn"` for safe rollout (log-only). Config: `prompt_injection_mode` ("warn"|"block"), `prompt_injection_block_threshold` (0.85), `prompt_injection_warn_threshold` (0.5). Called from `BaseAgentService.chat()` Phase 2. 42 detection tests + 12 blocking tests.
├── exceptions.py      # PromptInjectionBlockedError → HTTP 400; AgentExecutionError → HTTP 502; TransitDataError, ObsidianError, CircuitBreakerOpenError, AllProvidersUnavailableError → HTTP 503
├── validation.py      # Deterministic QA with severity-tagged Issues: route/stop plausibility + existence, delays, stale data, Latvian diacritics, time consistency, citation grounding, language match (AI-5.2)
├── correction.py      # AI-5.1/5.2 self-correction loop — bounded retry on error-severity validation failures (standard tier), instrumented with per-check metrics (AI-5.3)
├── metrics.py         # AI-5.3 in-process self-correction metrics tracker — per-check counters with lazy daily UTC reset
├── pipeline.py        # Multi-phase orchestrator for complex tier (own retry layer)
├── circuit_breaker.py # AI-8.1: async 3-state LLM provider breaker — `CircuitState` enum (CLOSED/OPEN/HALF_OPEN), frozen `BreakerConfig` (failure_threshold=5, recovery_timeout_s=30.0, success_threshold=2, window_size=20, failure_rate_threshold=0.5 — all env-var-backed via `Settings`), `CircuitBreaker.call(fn, /, *args, **kwargs) -> T` wrapper. Trips on consecutive-failure count OR sliding-window rate (rate trigger only arms once the window is full). Pluggable `time_fn` for `ManualClock` deterministic tests. `asyncio.Lock` guards state reads/writes; lock never held across the awaited `fn` call (3 separate acquisitions, mirrors `app/core/resilience.py`). Raises `CircuitBreakerOpenError(AgentError)` (HTTP 503). 7 log events under `agent.circuit_breaker.*` (opened/half_opened/closed/reopened/rejected/probe_success/probe_failure) — provider name + counters only, no credentials. Agent-module-local (not `app/shared/`) per three-feature rule. Kept separate from the GTFS-RT breaker at `app/core/resilience.py`. AI-8.3 wires `_execute()` through `llm.invoke_provider_chain()` behind the `circuit_breaker_enabled` kill switch.
├── llm.py             # AI-8.3: per-provider breaker registry + provider chain invoker. Module-level `_breakers: dict[str, CircuitBreaker]` lazy-init via `get_breaker(name, settings)`; read-only `get_breaker_state(name)` (returns CLOSED for unregistered providers) used by `provider_health.track_provider_call` to surface live state without coupling the tracker to breaker construction; `reset_provider_breakers()` test-only helper. `invoke_provider_chain[T](call, *, settings)` walks `[settings.llm_provider, settings.llm_fallback_provider]`, dispatches each call through `breaker.call(...)` (NOT a direct state check — must go through `_before_call` so OPEN→HALF_OPEN recovery transitions still fire after `recovery_timeout_s`), catches `CircuitBreakerOpenError` (logs `agent.provider_chain.preempted`), catches any other exception (logs `agent.provider_chain.fallback`), and on chain exhaustion logs `agent.provider_chain.exhausted` and raises `AllProvidersUnavailableError(providers_tried)`. When `circuit_breaker_enabled` is False the helper flattens to a single direct `await call(s.llm_provider)` with **zero** registry writes — preserves pre-AI-8 semantics byte-for-byte and lets Pydantic AI's `FallbackModel` handle the cascade as the belt-and-braces layer.
├── provider_health.py # AI-8.2: in-process per-LLM-provider health tracker — `ProviderHealth` dataclass (provider_name, CircuitState, total_calls/failures, last_success/failure_at, bounded 100-observation latency deque) + `ProviderHealthTracker` singleton with lazy 00:00 UTC daily reset (mirrors metrics.py). Exposes `track_provider_call()` async context manager wrapping the 3 LLM call sites in `service.py` (complex pipeline, correction loop, fallback `agent.run`) — fail-open so `record_call` errors never block LLM results. p50/p95 computed via `statistics.quantiles(method="inclusive")`; returns `None` below 2 observations. Admin-only `GET /v1/chat/provider-health` (60/min) renders deep-copied snapshots sorted by provider name. AI-8.3: `track_provider_call` now does a deferred `from app.core.agents.llm import get_breaker_state` (avoids module-load circular import) and forwards the live `CircuitState` to `record_call(state=...)` on both success and failure branches, so the admin endpoint sees the up-to-date breaker state.
├── context_budget.py  # AI-6.4: `ContextBudget(frozen=True)` dataclass + per-agent `AGENT_BUDGETS` dict + `agent_budget_for()` lookup. Default `skill_docs_max` 2000 tokens; transit=2500, knowledge=2000, vault=1500, unified=3000.
├── skill_loader.py    # AI-6.4: progressive L3 skill loader. Parses markdown files with YAML front matter (`yaml.safe_load` only), path-sandboxed via `Path.is_relative_to`, priority-gated (P1 always, P3 drops when remaining <70%, P2 drops when remaining <30%), token-budget-aware, keyword-filtered against lowercased prompt (never regex). Module-level cache keyed by domain; fail-open on every error path (logs `agent.skill_loader.*` and returns None/""). Public API: `SkillMeta`, `parse_skill_file()`, `discover_skills()`, `load_skills_within_budget()`, `clear_cache()`.
├── agent_result.py    # AI-6.5: `AgentResult(frozen=True)` dataclass — metadata-only wrapper built inside `BaseAgentService.chat()` from `_PipelineOutcome` + active domain. Fields: content (post _post_process), confidence (0..1 or None), warnings (metadata only — NOT rendered into content, that happens in _post_process earlier), tools_used, domain. `__post_init__` validates domain ∈ VALID_DOMAINS and confidence range.
├── skills/            # AI-6.4: in-repo L3 skill packs (markdown + YAML front matter, priority + token_cost + keywords). 5 transit (delay_analysis P2, schedule_interpretation P2, route_comparison P3, driver_availability P3, adherence_reporting P3), 4 knowledge (sop_retrieval P1 always-on, regulation_interpretation P2, shift_handover P3, incident_response P2), 3 vault (search_patterns P2, bulk_operations P3, folder_organization P3).
├── evals/             # AI-7.1: synthetic eval cases (YAML) + loader. 15 transit + 10 knowledge + 5 vault cases. Frozen `EvalCase` dataclass with `__post_init__` validation; loader is fail-open and path-sandboxed (mirrors skill_loader.py). AI-7.2: `runner.py` CLI + `EvalTrace` JSONL writer under `evals/traces/` (fail-open per case, path-sandboxed output, never logs prompts; `chat_with_trace()` on `BaseAgentService` exposes trace metadata). AI-7.3: `judge.py` Pydantic AI one-shot judge — grades each case across its 5 per-criterion descriptions (PASS/FAIL + ≤280-char reasoning). Fail-open per case, path-sandboxed JSONL under `evals/verdicts/`, never logs raw prompt/response. AI-7.4: `regression.py` per-criterion pass-rate baselines under `evals/baselines/{suite}_baseline.json` (committed), `check_regression()` with 3pp default tolerance, `make eval-judge` / `make eval-baseline` / `make eval-check` for CI gating, `--update-baseline` for intentional drift.
├── tools/
│   ├── transit/       # 5 read-only tools (GTFS-RT + static data, DB-backed)
│   │   ├── schemas.py, deps.py, client.py, static_cache.py, static_store.py
│   │   ├── query_bus_status.py      # Tool 1: status/route_overview/stop_departures
│   │   ├── get_route_schedule.py    # Tool 2: timetable by route/date/direction
│   │   ├── search_stops.py          # Tool 3: search by name or proximity
│   │   ├── get_adherence_report.py  # Tool 4: on-time performance metrics
│   │   ├── check_driver_availability.py # Tool 5: driver staffing queries
│   │   └── tests/                   # 104 tests
│   ├── obsidian/      # 4 read-write tools (Obsidian Local REST API)
│   │   ├── schemas.py, client.py
│   │   ├── query_vault.py           # Tool 6: search/tags/list/recent/glob
│   │   ├── manage_notes.py          # Tool 7: CRUD + frontmatter/section editing
│   │   ├── manage_folders.py        # Tool 8: folder CRUD (delete requires confirm)
│   │   ├── bulk_operations.py       # Tool 9: batch ops with dry_run preview
│   │   └── tests/                   # 68 tests
│   ├── knowledge/     # 1 read-only RAG search tool (with query router short-circuit)
│   │   ├── search_knowledge.py      # Tool 10: hybrid vector+fulltext, citations, confidence threshold, RAG router gate
│   │   └── tests/                   # 9 tests
│   └── skills/        # 1 skills management tool
│       └── manage_skills.py         # Tool 11: list/create operational skills
└── tests/             # 440+ agent-level tests (incl. routing, config tier, self-correction loop, severity-tier QA, correction metrics + admin endpoint, BaseAgentService hook-point tests in test_base.py, AI-6.4 context_budget/skill_loader, AI-6.5 AgentResult + confidence re-route gate, AI-8.1 circuit breaker transitions + concurrency + invariants in test_circuit_breaker.py, AI-8.2 provider health tracker + admin endpoint in test_provider_health.py, AI-8.3 chain registry + invoker in test_llm.py, AI-8.3 service-level chain integration in test_service.py::TestCircuitBreakerIntegration, AI-9.2 injection blocking mode in test_injection_blocking.py). `_reset_provider_breakers` autouse fixture in conftest.py clears the AI-8.3 registry around every test.
```

## Tool Docstring Guidelines

Tool docstrings differ from standard Google-style — they're read by LLMs during tool selection and must guide the agent to choose the RIGHT tool efficiently.

**Key Principles:**
1. **Guide Tool Selection** — help agent choose this tool over alternatives
2. **Prevent Token Waste** — steer toward efficient parameter choices
3. **Enable Composition** — show how tool fits multi-step workflows
4. **Set Expectations** — performance characteristics and limitations
5. **Provide Examples** — concrete usage with realistic data
