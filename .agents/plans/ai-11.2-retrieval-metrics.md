# Plan: AI-11.2 Retrieval Metrics — Relevance, Position, Completeness

## Context

Create `app/knowledge/evals/metrics.py` — computes three metrics per QA pair by replaying questions through `KnowledgeService.search()`:
1. **Relevance** — binary: was the source chunk in the top-k results? (recall@k)
2. **Position** — what rank did the source chunk receive? (MRR contribution)
3. **Completeness** — did retrieval surface all sibling chunks sharing the same parent/heading? (multi-chunk ground truth)

These metrics decompose retrieval quality for the RAG eval pipeline started in AI-11.1.

### Critical Design Constraint: chunk_id Matching

`SearchResult` does NOT expose `chunk.id` (the DB primary key). It exposes `document_id` + `chunk_index`. The search service has access to `chunk.id` internally (`chunk_data[cid]` at service.py:680) but doesn't pass it to the schema.

**Solution:** Add `source_chunk_index: int` to `QAPair` (contained within eval system, no API impact). The qa_generator already has `chunk.chunk_index` available at generation time (line 205-213). Metrics match by `(document_id, chunk_index)`.

### Completeness Ground Truth

For completeness, need the set of sibling chunk indices that share the same `parent_chunk_id` or `heading_path` as the source chunk. This requires a DB query. Design:
- Pure function `compute_pair_metrics()` takes `sibling_count: int` as parameter
- Async orchestrator `evaluate_pair()` queries DB for siblings, then calls the pure function

### Existing Schemas to Extend

`RetrievalMetrics` currently has: `total_pairs`, `recall_at_1`, `recall_at_5`, `mrr`.
Needs: `recall_at_3`, `recall_at_10`, `mean_completeness`. Keep existing fields, add new ones.

### Step 5: Create `app/knowledge/evals/metrics.py`

Core module with:

```python
"""Retrieval metrics computation for RAG evaluation.

Computes per-pair metrics (relevance, position, completeness) and
aggregates them into recall@k, MRR, and mean completeness scores.
"""

from __future__ import annotations

from app.core.logging import get_logger
from app.knowledge.evals.schemas import PairMetrics, QAPair, RetrievalMetrics
from app.knowledge.schemas import SearchResult

logger = get_logger(__name__)
```

**Functions:**

1. `compute_pair_metrics(qa_pair: QAPair, search_results: list[SearchResult], sibling_count: int = 1) -> PairMetrics`
   - Find source chunk in results by matching `(qa_pair.source_document_id, qa_pair.source_chunk_index)` against each result's `(document_id, chunk_index)`
   - `relevance_hit` = found in results
   - `rank` = 1-indexed position if found, else None
   - `mrr_contribution` = 1.0/rank if found, else 0.0
   - For completeness: count how many results share `qa_pair.source_heading_path` (via `heading_path` field) or share the same `parent_chunk_id` as the source. `completeness` = matched_siblings / sibling_count. If sibling_count <= 1, completeness = 1.0 if hit, 0.0 if miss.

2. `aggregate_metrics(per_pair: list[PairMetrics]) -> RetrievalMetrics`
   - `total_pairs` = len(per_pair)
   - `recall_at_1` = fraction where rank is not None and rank <= 1
   - `recall_at_3` = fraction where rank is not None and rank <= 3
   - `recall_at_5` = fraction where rank is not None and rank <= 5
   - `recall_at_10` = fraction where rank is not None and rank <= 10
   - `mrr` = mean of mrr_contribution
   - `mean_completeness` = mean of completeness
   - Handle empty list: return all zeros

3. `_find_source_rank(qa_pair: QAPair, search_results: list[SearchResult]) -> int | None`
   - Internal helper: iterate results, match by (document_id, chunk_index), return 1-indexed rank or None

4. `_count_sibling_hits(qa_pair: QAPair, search_results: list[SearchResult]) -> int`
   - Internal helper: count results sharing the same `heading_path` as `qa_pair.source_heading_path` (when not None), OR sharing the same `parent_chunk_id` (when not None)
   - Used by completeness calculation
